# 每 1 秒打印系统状态监控任务

## 需求 → 方案映射

| 需求字段 | 实现来源 | 额外代码 |
|---|---|---|
| 内存已使用 | `configTOTAL_HEAP_SIZE(40KB) - xPortGetFreeHeapSize()` | 无 |
| 内存未使用 | `xPortGetFreeHeapSize()` | 无 |
| 最大使用(历史峰值) | `40KB - xPortGetMinimumEverFreeHeapSize()` | 无,heap_4 内核自带 |
| 最小剩余(历史最低) | `xPortGetMinimumEverFreeHeapSize()` | 无,heap_4 内核自带 |
| CPU 占用率 | 启用 `configGENERATE_RUN_TIME_STATS`,忙占比 = 100% − 空闲任务运行占比 | TIM11 统计时钟 + 配置宏 |

CPU 占用率现状:工程未开 run-time stats(`config/FreeRTOSConfig.h` 无 `configGENERATE_RUN_TIME_STATS`)。采用 FreeRTOS 官方做法:闲置的 **TIM11**(APB2, 168MHz,工程仅 Base_Init,无 NVIC/中断句柄)配成 1MHz 自由计数器(≥tick 10 倍的标准要求),16 位每 65.5ms 溢出,由溢出中断把高位计入软件计数,合成 32 位虚拟计数器。

## 改动文件(共 6 处)

1. **新建 `bsp/components/rtstats/rtstats_tim.c/.h`**(BSP 层,仿 `led_pwm.c` 的目录组织):`rtstats_rtclock_init()` 配 TIM11 PSC=167→1MHz、使能 NVIC(`TIM1_TRG_COM_TIM11_IRQn`,优先级 15)、`HAL_TIM_Base_Start_IT`;中断句柄直接读/清 UIF 并累加溢出计数(不经过 `HAL_TIM_PeriodElapsedCallback`——该回调已被 main.c 的 TIM7 时基占用,避免符号冲突);`rtstats_rtclock_get()` 用"读溢出→读CNT→复读溢出"消除撕裂,返回 32 位值。

2. **`config/FreeRTOSConfig.h` + `Inc/FreeRTOSConfig.h` 两份同步修改**(CubeMX 编译单元中 `Inc/` 排在 `config/` 之前,只改一份会导致不同编译单元 TCB 布局不一致 → 内存踩踏)。在 USER CODE Defines 区(L170)加:
   ```c
   #define configGENERATE_RUN_TIME_STATS 1
   #define INCLUDE_xTaskGetIdleTaskHandle 1
   #define portCONFIGURE_TIMER_FOR_RUN_TIME_STATS()  rtstats_rtclock_init()
   #define portGET_RUN_TIME_COUNTER_VALUE()          rtstats_rtclock_get()
   ```
   (含 extern 声明;仿 L67-68 风格注明"CubeMX 重新生成会丢")

3. **新建 `app/tasks/monitor_task.c`**(仿 `dashboard_task.c` 结构):`StartMonitorTask` 用 `osDelayUntil` 精确 1s 节拍,每周期:喂狗(跟随 dashboard 约定)→ `vTaskGetInfo(xTaskGetIdleTaskHandle(), ...)` 取空闲任务运行时增量 → 计算 CPU 忙占比(整数 0.1% 精度,不用浮点,FPU 未开)→ 取堆三项 + 总量 → **一条 `dbg_printf` 打一行**(≤160B 缓冲):
   ```
   [mon] cpu 12.3% | heap total 40960 used 12345 free 28615 peak_used 15000 min_free 25960
   ```

4. **`app/tasks/freertos.c`** 三处锚点:Variables 区加 `monitorTaskHandle` + attributes(`"monitorTask"`,栈 `512*4`=2KB、优先级 `osPriorityBelowNormal`,后台监控不挤占 UI);FunctionPrototypes 区(L101-110)加原型;RTOS_THREADS 区(L147-153)加 `osThreadNew`。
   栈取 2KB 因堆吃紧:40KB − 5 个任务已占 ~30KB + LwIP,再省则让 malloc hook 兜底(打印后 IWDG 复位,串口可见)。

5. **根 `CMakeLists.txt`**:`target_sources` 加 `bsp/components/rtstats/rtstats_tim.c` 和 `app/tasks/monitor_task.c`;`target_include_directories` 加 `bsp/components/rtstats`。

6. **README「当前进度」**同步(验证通过后)。

## 验证闭环(stm32-debug-loop skill)

编译 → ST-Link 烧录 → COM18@115200 串口捕获,检查:
- 每秒稳定输出一行 `[mon]`,数值格式正确
- CPU% 合理:桌面静置偏低、LVGL 渲染时上升;heap used/free 与 40KB 总量自洽;peak_used ≥ used、min_free ≤ free
- 无 malloc-failed hook 复位、无栈溢出复位;原有 dash/lvgl/key 日志不受干扰
- 首行打出的 free heap 同时确认堆余量健康

验证通过后按约定更新 README 并 conventional commit(中文)。

## 已知取舍

- CPU% 精度 ±0.1%(1MHz 统计时钟,1s 窗口,误差 ≤ 一个时间片)
- `dbg_printf` 沿用现状无锁:1Hz 低频,与现有任务用法一致,单行单次 Transmit
- 每任务 CPU 分解、栈高水位不在本次需求内,后续可基于同一 run-time stats 机制扩展
